# 포트폴리오 최적화 결과 ,  2026-11-18

현재 포트폴리오 저장소를 대상으로 작업했습니다. 기존 화면을 유지하고 신규 Vue 컴포넌트를 추가로 쪼개지 않았습니다. 별도 프레임워크의 인풋 데모는 이번 범위에 포함하지 않았습니다.

## 성능 측정

Lighthouse 12.8.2의 모바일 시뮬레이션(네트워크 왕복 지연 시간(RTT) 150ms, 1,638.4Kbps, CPU 4배 감속)으로 gzip을 제공하는 로컬 정적 빌드를 측정했습니다. 실서비스 PageSpeed Insights나 CrUX 실사용 데이터가 아닙니다. 캐시 정책, 배포 환경, 분석 태그, 실행 시점에 따라 점수는 달라집니다.

- 메인 성능: **87 → 96점**. LCP **3.77 → 2.63초**, 전송량 **784.6 → 262.4KiB** (66.6% 감소).
- 최종 프로젝트 목록 성능: **96점**, 상세 성능: **98점**. 목록, 상세의 변경 전 점수는 측정하지 않았습니다.
- 최종 세 화면의 접근성, 권장사항, SEO: **각각 100점**. CLS는 세 화면 모두 **0**입니다.
- 메인 HTML: **118,060 → 68,448바이트**. 인라인 CSS: **92,941 → 40,923바이트**.
- 측정 원본 수치: [performance-2026-11-18.json](performance-2026-11-18.json).

## 데이터 로딩과 이미지

- 전체 프로젝트 원문을 공통 번역 번들에서 제거했습니다. 원본은 data/works/ko.json과 en.json에 보관하고, 빌드 시 목록 요약과 개별 프로젝트 JSON으로 생성합니다.
- useAsyncData의 언어, 프로젝트별 키, 정적 페이로드, 얕은 데이터 참조를 사용합니다. 정렬은 원본을 복사해 처리하며, 초기 수화 시 같은 데이터를 다시 다운로드하지 않습니다.
- SSR에서도 정적 JSON과 같은 레코드를 제공하고, 정적 호스팅에서는 생성한 파일을 읽습니다. 영어 전환과 SPA 이동도 검증했습니다.
- BaseMediaImage가 이미지 크기를 선언하고 160, 320, 480, 960, 1440px 범위에서 실제 원본 크기에 맞는 WebP를 선택합니다. sizes는 히어로, 카드, 기기 목업, 상세, 썸네일의 표시 크기에 맞췄습니다.
- 첫 화면의 핵심 이미지만 eager/high 우선순위를 사용하고, 나머지는 지연 로드합니다. 역량 미리보기는 선택된 이미지 한 장만 렌더링합니다.
- 링크는 화면에 보인다는 이유로 모든 프로젝트를 미리 가져오지 않고 상호작용 시 프리패치합니다.

## Vue, SCSS와 미사용 코드

- 사용되지 않는 이전 홈 섹션, 렌더러, 헤더, 독, 메뉴, 보기 모드 및 저장소 연동 코드를 제거했습니다. 실제로 참조하는 컴포넌트와 함수만 남았는지 다시 확인했습니다.
- GSAP, Three.js와 관련 타입 의존성을 제거했습니다. Nuxt 3.21.11, Vue 3.5.45 및 이미지 빌드용 Sharp 0.35.5로 검증했습니다.
- Sass 변수와 믹스인은 CSS를 출력하지 않는 _mixins.scss로 분리했습니다. 전역 CSS 토큰은 한 번만 출력하고, 홈, 소개, 경력, 갤러리 목록, 상세 스타일은 각 화면에서 로드합니다.
- 중복되는 갤러리 레이아웃 래퍼와 갤러리 통합 스타일 진입점을 제거했습니다. 재사용 사례 카드의 스타일도 해당 컴포넌트에서 불러옵니다.
- 미사용 CSS 변수, 믹스인, 구형 클래스 선택자, 번역, 이미지, 아이콘 파일을 정리했습니다. 아이콘 출처와 라이선스는 보관했습니다.
- 등장 효과는 SSR과 첫 화면을 숨기지 않습니다. 화면 아래 항목만 단일 IntersectionObserver로 처리하고 MutationObserver, 숫자 카운터 루프와 상시 will-change를 제거했습니다.

## 데모 페이지 정리

- 디자인 토큰과 컴포넌트 카탈로그 페이지 및 진입 버튼을 삭제했습니다.
- 페이지 전용 번역, 샘플 데이터, 데모에서만 사용하던 컴포넌트와 스타일을 제거했습니다.
- 실제 화면에 쓰는 SCSS 토큰과 공통 스타일은 유지합니다.

## SEO, GEO, AEO

- 본인 FAQ 화면, 번역 데이터, FAQPage 구조화 데이터와 llms.txt의 FAQ를 제거했습니다.
- Person 식별자, 영문 이름 표기, GitHub 식별자, WebSite, ProfilePage, BreadcrumbList, 프로젝트 CreativeWork와 실제 본문 정보를 일관되게 연결했습니다.
- 프로젝트 제목을 이름, 역할과 연결하고 canonical, 설명, OG 이미지 정보를 정리했습니다.
- 프로젝트 원본에서 사이트맵, RSS, llms.txt를 생성하므로 링크 목록과 공개 프로젝트가 어긋나지 않습니다. 존재하지 않는 별도 언어 URL이나 보이지 않는 FAQ는 추가하지 않았습니다.
- robots.txt의 기존 전체 수집 허용을 확인했습니다. 수집을 허용하는 것과 실제 검색, AI 인용 순위는 별개입니다.

Google의 [AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)는 일반 검색과 같은 기술적 접근성, 유용한 공개 본문, 본문과 일치하는 구조화 데이터를 강조합니다. [OpenAI 검색 크롤러 안내](https://developers.openai.com/api/docs/bots) 및 [네이버 robots.txt 안내](https://searchadvisor.naver.com/guide/seo-basic-robots)도 참고했습니다. 검색 1위나 AI 답변의 첫 번째 인용은 보장할 수 없습니다.

배포 후에는 실제 도메인으로 PageSpeed Insights를 다시 측정하고, Search Console, 네이버 서치어드바이저의 소유 확인, 사이트맵, RSS 제출 및 수집 상태를 확인해야 합니다. 사이트 순위나 실서비스 색인 상태가 이번 로컬 검증으로 변경됐다고 보지는 않습니다.
