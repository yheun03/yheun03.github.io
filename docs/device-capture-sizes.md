# 목업별 캡처 크기

기기 외곽 PNG 크기와 화면 안쪽 크기는 다르다. 캡처는 안쪽 화면의 비율에 맞추며, 웹사이트는 아래 CSS 뷰포트 크기로 연다. 기기 원본 픽셀 크기를 그대로 모바일 뷰포트로 사용하면 PC 레이아웃이 표시될 수 있으므로 구분한다.

## 맥북

- 프레임: `assets/images/devices/macbook.webp`, 3306 × 1897 px
- 원본 화면: 2560 × 1600 px, 시작 좌표 x=373, y=123
- 캡처 뷰포트: 1280 × 800 CSS px
- 원본 화면과 캡처의 대응 배율: 2:1
- 화면 비율: 16:10

- 캡처 뷰포트: 1024 × 1366 CSS px
- 원본 화면과 캡처의 대응 배율: 2:1

## 캡처 및 적용 기준

- 기본 캡처는 브라우저의 뷰포트를 해당 크기로 설정해 현재 화면을 저장한다. 필요하면 전체 페이지 캡처도 사용하며, 이때도 이미지별 기기 설정과 가로 폭 맞춤, 상단 고정 기준을 유지한다.
- 뷰포트 캡처 파일의 최종 픽셀 크기는 위 CSS 뷰포트 크기와 같다. 브라우저가 이미지를 약간 축소해 반환하면 전체 화면 내용을 자르지 않고 비율을 유지해 목표 크기로 정규화한다. 대응 배율은 목업 원본과 캡처 크기의 관계이며, 브라우저의 기기 배율 설정을 의미하지 않는다.
- 라이트 모드에서 지도, 이미지, 웹폰트와 등장 효과가 표시된 뒤 저장한다. 카카오톡 클론은 다크 단일 디자인을 유지한다.
- 크기 전환이나 새로고침으로 테마가 바뀌지 않았는지 기기별로 확인한다.
- 화면 이미지는 `width: 100%`, `height: auto`로 목업 화면의 좌우 폭에 맞추고 상단에 배치한다. 원본 비율을 유지하며, 화면보다 긴 부분은 화면 영역의 `overflow: hidden`으로 아래쪽에서 자른다.
- 긴 PC 전체 페이지 캡처와 모바일 캡처가 섞인 프로젝트는 `captureDevices`에 이미지 경로별로 `desktop`, `tablet`, `mobile`을 명시한다. 목록은 대표 이미지의 설정을, 상세는 현재 선택한 이미지의 설정을 우선 적용한다. 프로젝트 전체를 한 기기로 강제하지 않는다.
- 스마트팩토리 정부 사업은 1~3번 PC, 4~5번 모바일이며, 자사 홈페이지 리뉴얼 2022는 1번 PC, 2번 모바일이다. 두 프로젝트의 대표 카드는 맥북으로 표시한다.
- 전체 페이지 캡처도 사용할 수 있다. 세로 길이로 PC와 모바일을 추정하지 않으며, 이미지별 설정이 없으면 기기가 명시된 파일명(`tablet`, `mobile`)을 확인하고 나머지는 PC를 기본값으로 사용한다. 일반 파일명의 모바일 캡처는 반드시 `captureDevices` 또는 `mockup.mobile`에 기기를 명시한다.
- 공개 사이트에서 다시 캡처할 수 있는 이미지만 교체한다. 과거 실무 자료와 보안상 비공개 자료는 기존 원본과 안내를 유지한다.
- 새로 캡처할 때 `data/works/ko.json`, `en.json`의 `captures`, `mockup`, `captureLabels` 연결을 유지한다.
- 캡처 교체 후 `npm run prepare:assets`로 반응형 이미지를 갱신하고, 대표 이미지가 바뀌면 `node scripts/generate-og-images.mjs --details-only`로 공유 이미지를 갱신한다.

기기별 프레임 배치와 화면 좌표는 `components/work/ProjectDeviceMockup.vue`에서 관리한다. 출처와 라이선스는 `assets/images/devices/LICENSE.txt`를 참고한다.

## 적용 기록

2026-11-19 기준 공개 사이트 캡처 39장을 위 규격으로 교체했다. 맥북 15장, 아이패드 세로 7장, 아이패드 가로 1장, 아이폰 16장이다. 카카오톡 클론의 아이폰 캡처 3장은 다크 단일 디자인을 유지한다. 과거 실무 캡처와 비공개 안내 등 기존 자료 51개는 변경하지 않았다.
